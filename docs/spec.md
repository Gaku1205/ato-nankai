# 仕様書

アプリの「何を・どう動かすか」を書く。AIは作業の前に必ずここを読む。

## 目的

専門学校・大学生向けに、授業ごとの欠席を1タップで数え、単位を落とさずにあと何回休めるかを大きな数字で出すスマホ向けWebアプリ（元のメモ：あと何回休める？ 専門学校・大学生向け。授業ごとに欠席を1タップで数えて、単位を落とさずにあと何回休めるかを出すスマホ向けWebアプリ。ログイン無し・データは端末だけ）

## 前提

- 使う人：専門学校・大学の学生。授業の前後や休むと決めた朝に、スマホで1日に数回開く
- 技術：Next.js（App Router）＋TypeScript、テストはVitest
- ログイン無し・サーバー保存無し・課金無し。データはその端末のブラウザ（`localStorage`）だけに残る
- 曜日は月〜金、時限は1〜6限（土日の授業は後で足せる形にしておく）
- 配色は端末の設定（`prefers-color-scheme`）に合わせて、明るい配色と暗い配色を自動で切り替える。アプリの中に手動の切り替えは無い（色は `docs/design.md`）

## データの形

型は `src/lib/types.ts`、計算は `src/lib/remaining.ts`、保存は `src/lib/storage.ts`。

### 授業（Course）

| 項目 | 型 | 中身 |
| --- | --- | --- |
| `id` | 文字列 | 端末の中で一意（作るときに自動で付ける） |
| `name` | 文字列 | 授業の名前。前後の空白を取り、1〜40文字 |
| `weekday` | 1〜5 | 曜日。1＝月、2＝火、3＝水、4＝木、5＝金（JavaScript の `Date#getDay()` と同じ数） |
| `period` | 1〜6 | 時限 |
| `limit` | 下の「欠席の上限」 | 回数か時間数のどちらか |
| `latesPerAbsence` | 整数（任意） | 遅刻・早退が何回で欠席1回か。2〜20。無い＝換算しない（初めは無い）。読むとき範囲外・整数でないものは無いものとして扱う |

1つのマス（曜日×時限）に置ける授業は1つだけ。同じマスに保存すると、そのマスの授業を上書きする。

### 欠席の上限（limit）

学校ごとに決め方が違うので、次の2つから授業ごとに選ぶ。

- 回数で決める：`{ kind: "count", max: 整数 }`。`max` は 0〜99。「欠席は4回まで」なら `max: 4`
- 時間数で決める：`{ kind: "hours", maxHours: 数, hoursPerClass: 数 }`。`maxHours`（欠席してよい合計時間）は 0〜999、`hoursPerClass`（1回の授業が何時間か）は 0.5〜12。どちらも 0.5 刻み。「欠席は6時間まで、1コマ1.5時間」なら `maxHours: 6, hoursPerClass: 1.5`

### 欠席の記録（Absence）

| 項目 | 型 | 中身 |
| --- | --- | --- |
| `id` | 文字列 | 端末の中で一意 |
| `courseId` | 文字列 | どの授業の欠席か |
| `date` | `YYYY-MM-DD` | 欠席した日。「欠席 +1」を押した日（端末の時計の今日）を自動で入れる |

1件＝1回の欠席。授業を消したら、その授業の欠席の記録も消す。

### 遅刻・早退の記録（Late）

| 項目 | 型 | 中身 |
| --- | --- | --- |
| `id` | 文字列 | 端末の中で一意 |
| `courseId` | 文字列 | どの授業の記録か |
| `date` | `YYYY-MM-DD` | 遅刻・早退した日。「遅刻 +1」「早退 +1」を押した日（端末の時計の今日）を自動で入れる |
| `kind` | `"late"` か `"early"` | 遅刻か早退か |

1件＝1回。授業を消したら、その授業の遅刻・早退の記録も消す（同じマスを別の授業で上書きしたときも同じ）。

### 保存

- `localStorage` のキー `ato-nankai:v1` に、`{ "version": 1, "courses": [...], "absences": [...], "lates": [...] }` を JSON で入れる
- 読むとき、値が無い・JSON でない・形が違う（`version` が 1 でない、`courses`・`absences` が配列でない）ときは、空（授業0・欠席0・遅刻0）として扱う。配列の中の1件だけ形が違うときは、その1件だけを捨てる
- `lates` が無い・配列でないとき（遅刻・早退を入れる前に保存されたデータ）は、空の配列として読む。授業・欠席は消さない
- 欠席・遅刻・早退を足す・取り消す・授業を保存・削除・`latesPerAbsence` を変えるたびに、すぐ書き込む
- 別のタブで書き換えられたら（`storage` イベント）、読み直す

## 残り回数の計算

- 換算後の欠席数 ＝ 欠席の件数 ＋ ⌊（遅刻と早退の合計件数）÷ `latesPerAbsence`⌋（切り捨て。余りは次に持ち越す）。`latesPerAbsence` が無いときは遅刻・早退を数に入れない
  - 例：3回で欠席1回なら、遅刻2回は0回分、遅刻2＋早退1回で1回分、6回で2回分
  - 以下の「欠席数」はこの換算後の数。トップ・時間割・詳細の数字すべてに使う
- 回数の授業：残り回数 ＝ `max − 欠席数`
- 時間数の授業：残り時間 ＝ `maxHours − 欠席数 × hoursPerClass`、残り回数 ＝ 残り時間 ÷ `hoursPerClass` を切り捨てた数
  - 例：上限6時間・1回1.5時間・欠席1回 → 残り4.5時間 → あと3回
  - 例：上限5時間・1回1.5時間・欠席0回 → 残り5時間 → あと3回（3.33… を切り捨て）
- どちらも0より小さくならない（上限を超えて休んでも「あと0回」「あと0時間」）
- 残りの段（見た目を変える区切り。色・大きさは `docs/design.md`）
  - 0回：`zero`
  - 1回：`one`
  - 2〜3回：`few`
  - 4回以上：`safe`

### 今日のコマの並べ方

- 端末の今日の曜日と同じ `weekday` の授業だけを取り出す（土・日は0件）
- 残り回数の少ない順に並べる。同じ回数なら時限の早い順
- 先頭（残りがいちばん少ない授業）を、トップの大きな数字にする

## 画面

### トップ（`/`）

開いて最初に出すのは今日のコマだけ。

- いちばん上の行：今日の日付（例「11月19日（木）」）と、右に時間割づくり（`/timetable`）へのリンク「時間割」・設定（`/settings`）へのリンク「設定」
- 今日のコマがあるとき
  - 残りがいちばん少ない授業を1つ、画面の幅いっぱいの面に出す：時限（例「2限」）、授業の名前、「あと」＋残り回数の数字（画面いっぱいの大きさ）＋「回」。時間数の授業は、その下に「あと〇時間」を小さく添える（例「あと4.5時間」）。面のいちばん下に「欠席 +1」ボタン
  - ほかの今日のコマを、その下に並べ方の順で1行ずつ出す：時限、授業の名前、「あと〇回」（時間数の授業は「あと〇時間」を小さく添える）、「欠席 +1」ボタン
- 「欠席 +1」を1回押すと、その授業に今日の日付の欠席が1件足され、数字がすぐ1減る。並び順もすぐ並べ直す（大きな数字の授業が入れ替わることもある）
- 残りが0回の授業で「欠席 +1」を押したときは、足す前に確認を出す
  - 見出し「受験資格がなくなるかも」、本文「『{授業名}』はもう休める回数が残っていません。欠席を足しますか？」
  - ボタン「足す」（押すと足す）と「やめる」（何もしない）。確認の外を押す・Esc でも「やめる」と同じ
- 欠席を足したら、画面の下に「{授業名}に欠席を1件足しました」と「取り消す」ボタンを約5秒出す
  - 「取り消す」を押すと、いま足した1件を消して、案内も消す
  - 5秒たつと案内は消える（記録はそのまま）。続けて別の欠席を足したら、案内は新しい1件のものに替わり、5秒を数え直す
  - ほかの日付の欠席の取り消しは授業の詳細（`/class/?id=<授業のid>`）でやる
- 授業の名前（主役の面・行）を押すと、その授業の詳細を開く。「欠席 +1」ボタンとは別に、主役の面では授業名、行では授業名の部分がリンクになる
- 今日のコマが無い日（その曜日に授業が無い・土日）：「今日（{曜日}）は授業がありません」と、時間割づくりへのリンク「時間割を見る」
- 授業がまだ1つも無いとき：「まず時間割を作りましょう」「授業を入れると、ここに『あと何回休めるか』が出ます」と、ボタン「時間割を作る」（`/timetable` へ）
- 読み込み中（端末の保存を読む前、サーバーで作った最初の表示）は、日付の行だけを出す

### 時間割づくり（`/timetable`）

- いちばん上の行：見出し「時間割」と、トップへ戻るリンク「今日」
- 曜日（月〜金）×時限（1〜6限）の表。左端の列に時限の番号、いちばん上の行に曜日。今日の曜日の見出しだけ目立たせる
- 授業が入ったマス：残り回数の数字（主役）と授業の名前。残りの段で見た目を変える（トップと同じ段）
- 空きコマ：「＋」だけ
- マスを押すと、そのマスの編集の画面（下から出る）を開く
  - 見出し：「{曜日}曜 {時限}限」（例「木曜 2限」）
  - 「授業の名前」：文字の入力欄（例の文字は入れない。空のまま）
  - 「上限の数え方」：「回数」と「時間数」の切り替え（2つのボタン。初めは「回数」）
  - 回数のとき：「欠席できる回数」（0〜99の整数、単位「回」）
  - 時間数のとき：「欠席できる時間」（0〜999、0.5刻み、単位「時間」）と「1回の授業の時間」（0.5〜12、0.5刻み、単位「時間」。初めは 1.5）
  - ボタン「保存」：名前が空・数が範囲の外なら保存せず、入力欄の下に「授業の名前を入れてください」「0〜99の数を入れてください」のように出す
  - 授業が入ったマスを開いたときは、今の中身を入れておき、「この授業を消す」ボタンも出す。押すと「『{授業名}』と欠席の記録を消しますか？」の確認を出し、「消す」で消す
  - 「やめる」・外を押す・Esc で何も変えずに閉じる
- 授業の欠席数はそのまま残す（上限を変えたら、残り回数は新しい上限で計算し直す）。遅刻・早退の記録と `latesPerAbsence` も、上限を変えてもそのまま残す
- 授業が入ったマスの編集の画面には、「授業の詳細を見る」リンクを出す（押すと `/class/?id=<授業のid>` へ。欠席・遅刻の記録と取り消しはそこ）

### 授業の詳細（`/class/?id=<授業のid>`）

授業ごとの欠席・遅刻・早退の記録を見て、取り消し、遅刻の換算を決める。

- 存在しない `id`（保存データに無い授業）：「授業が見つかりません」と、トップへのリンク「今日に戻る」
- 読み込み中（端末の保存を読む前）は、戻るリンクだけを出す
- いちばん上の行：戻るリンク「今日」（`/` へ）。右に「時間割」（`/timetable` へ）
- 残りの面：トップの主役と同じ段の面（授業名、「あと」＋残り回数＋「回」、時間数の授業は「あと〇時間」）。ただし「欠席 +1」ボタンは無く、高さも小さい。授業名の上に「{曜日}曜 {時限}限」
- 欠席：見出し「欠席」と件数。日付ごとに新しい順（同じ日に何件あっても1件ずつ並べる）で、1行に「11月12日（木）」と「取り消す」ボタン
  - 「取り消す」を押すと、その1件だけが消え、残り回数がすぐ戻る。確認は出さない
  - 0件のときは「欠席はまだありません」
- 遅刻・早退：見出し「遅刻・早退」。ボタン「遅刻 +1」「早退 +1」を横に並べる（日付は端末の今日。過去の日付を選んで足す入力は無い）
  - 記録の一覧：日付ごとに新しい順。1行に「11月12日（木）」「遅刻」か「早退」と「取り消す」ボタン。1件ずつ確認なしで消す
  - 0件のときは「遅刻・早退はまだありません」
  - 残りが0回の授業で足しても、確認は出さない
- 換算の設定：見出し「遅刻・早退の換算」。選択式の入力「遅刻・早退が何回で欠席1回」。選べるのは「換算しない」（初めの値）と 2〜20 回
  - 変えるとすぐ保存し、残り回数（詳細・トップ・時間割）をすぐ計算し直す
  - 換算するときは、入力の下に「いま遅刻・早退 {n}回 → 欠席 {k}回分」を出す（`k` は切り捨てた数）。換算しないときは「換算しないので、遅刻・早退は残り回数に入りません」
- 授業の名前・曜日・上限の編集はここでは出来ない（時間割づくりでやる）

### 設定（`/settings`）

ロジックは書き出し・読み込みが `src/lib/backup.ts`、学期の引き継ぎが `src/lib/term.ts`。

- いちばん上の行：見出し「設定」と、右にリンク「今日」（`/`）・「時間割」（`/timetable`）
- 3つの項目を縦に並べる（明るい・暗いは端末の設定に自動で合わせるので、項目は無い）

#### 書き出し

- 説明「授業と欠席の記録を、ファイルに書き出します。機種変更のときに、新しい端末で読み込めます。」、ボタン「書き出す」
- 押すと、保存データ（`AppData`）を JSON（`{ "version": 1, "courses": [...], "absences": [...] }`、保存形式そのまま、字下げ2文字）のファイルとしてダウンロードする。ファイル名は `ato-nankai-YYYY-MM-DD.json`（端末の今日の日付）
- 押したあと、項目の中に「ato-nankai-2026-11-19.json を書き出しました」と出す

#### 読み込み

- 説明「書き出したファイルから、授業と欠席の記録を戻します。今のデータは置き換わります。」、ボタン「ファイルを選ぶ」（`.json` のファイルを選ぶ）
- ファイルを選んだら、まず中身を調べる（検証）。ここでは今のデータを変えない
  - 通らないとき：項目の中に赤い文字で「読み込めませんでした。{理由}」を出す。今のデータは変えない
  - 通ったとき：確認を出す。見出し「今のデータを置き換えます」、本文「ファイルの授業{n}件・欠席の記録{m}件で、今の授業と欠席の記録をすべて置き換えます。よろしいですか？」、ボタン「置き換える」（押すと保存して置き換える）と「やめる」（何もしない。外を押す・Esc でも同じ）
  - 置き換えたら、項目の中に「授業{n}件・欠席の記録{m}件を読み込みました」と出す
- 検証：次のどれかに当てはまるファイルは、**まるごと読み込まない**（`parseData` のように1件だけ捨てて通すことはしない）。理由の文は括弧の中
  - JSON として読めない（「JSONのファイルではありません」）
  - 中身がオブジェクトでない（「あと何回休める？の書き出しファイルではありません」）
  - `version` が 1 でない（「あと何回休める？の書き出しファイルではありません（versionが1ではありません）」）
  - `courses`・`absences` が配列でない（「授業か欠席の記録の形が違います」）
  - 授業の1件でも形が違う（「授業の{n}件目の形が違います」。n は 1 から数える。形は「データの形」の Course と同じ）
  - 欠席の記録の1件でも形が違う（「欠席の記録の{n}件目の形が違います」）
  - 同じマス（曜日×時限）に授業が2つある（「同じ曜日・時限に授業が2つあります」）
  - 授業の `id` が重なっている（「授業のidが重なっています」）／欠席の記録の `id` が重なっている（「欠席の記録のidが重なっています」）
  - 欠席の記録の `courseId` に、ファイルの中に無い授業がある（「授業が見つからない欠席の記録があります」）
- ファイルを読む途中で失敗したとき：「ファイルを読めませんでした」
- 書き出したファイルを、そのまま読み込むと、同じ状態に戻る

#### 学期の引き継ぎ

- 説明「学期が終わったら、時間割と授業は残したまま、欠席の記録だけを消します。残り回数は上限に戻ります。」、ボタン「欠席を0に戻す」
- 押すと確認を出す。見出し「欠席の記録を消します」、本文「時間割と授業は残ります。欠席の記録{m}件が消えて、すべての授業の残り回数が上限に戻ります。元には戻せません。」、ボタン「消す」（押すと消す）と「やめる」
- 消したら、項目の中に「欠席の記録{m}件を消しました」と出す。欠席の記録が0件のときの本文は「欠席の記録はまだありません。」、押しても何も変わらず「欠席の記録はありません」と出す（確認は出さない）
- 消すのは欠席の記録（`absences`）と遅刻・早退の記録（`lates`）だけ。授業（`courses`）と `latesPerAbsence` は変えない。上の文は遅刻・早退も数えて「欠席・遅刻・早退の記録{m}件」（`m` は両方の合計）と読み替える（説明は「欠席・遅刻・早退の記録だけを消します」、確認の見出しは「欠席・遅刻・早退の記録を消します」、0件のときは「欠席・遅刻・早退の記録はありません」）
- 書き出し・読み込みは `lates` も含める。読み込むファイルに `lates` が無いときは空として読む。あるのに配列でない、1件でも形が違う・`id` が重なる・`courseId` の授業がファイルに無いときは、欠席の記録と同じく読み込まない（「遅刻・早退の記録の{n}件目の形が違います」など）
